## Week 1 — เรียก LLM ในเครื่องตัวเอง

เป้าหมายสัปดาห์นี้: ให้คุณรันโค้ดที่ "คุยกับ AI" บนเครื่องตัวเองได้ ฟรี ไม่ต้องสมัคร API key
และเข้าใจว่าการเรียก LLM ก็คือการยิง HTTP API ธรรมดาที่คุณทำอยู่แล้วทุกวัน

### สิ่งที่ต้องติดตั้ง (ทำครั้งเดียว)

#### 1. Python

**Windows:**
```powershell
winget install Python.Python.3.12
```
ปิดแล้วเปิด terminal ใหม่ แล้วเช็ค: `python --version`

#### 2. Ollama (ตัวรัน LLM ในเครื่อง ฟรี)

โหลดที่ [ollama.com/download](https://ollama.com/download) แล้วลงตัวติดตั้งเหมือนโปรแกรมทั่วไป
(Windows ติดตั้งแล้วจะรันเองใน background)

ดึงโมเดลขนาดเล็ก (~1.9 GB) — qwen2.5 เล่นภาษาไทยได้ค่อนข้างดี:
```powershell
ollama pull qwen2.5:3b
```

ลองคุยกับมันตรงๆ เช็คว่าทำงาน:
```powershell
ollama run qwen2.5:3b "สวัสดี"
```

#### 3. ติดตั้ง package ของโปรเจกต์

```powershell
cd <โฟลเดอร์ที่ clone repo นี้มา>
pip install -r requirements.txt
```

### รันตัวอย่าง (ทำตามลำดับ)

```powershell
python 01_call_api_raw.py        # เรียก LLM ด้วย HTTP เปล่าๆ ไม่มี library
python 02_ollama_package.py      # เรียกผ่าน package สำเร็จรูป
python 03_chat_with_history.py   # แชทวนลูป เห็นว่า "ความจำ" ของ LLM ทำงานยังไง
```

### ให้สังเกตอะไร

- **ตัวอย่าง 1:** การเรียก AI คือ `POST /api/generate` ส่ง JSON `{"model": ..., "prompt": ...}` — เหมือน API ที่คุณเขียนเองทุกวัน
- **ตัวอย่าง 2:** มี `role: "system"` สำหรับตั้งกฎให้โมเดล กับ `role: "user"` สำหรับคำถาม
- **ตัวอย่าง 3:** LLM **จำอะไรไม่ได้เลย** — เราต้องส่งประวัติแชททั้งหมดกลับไปทุกรอบ ลองถาม "ผมชื่อ Rachen" แล้วถามต่อว่า "ผมชื่ออะไร" จะเห็นว่ามันจำได้เพราะเราส่งประวัติกลับไป ไม่ใช่เพราะมันฉลาด

สิ่งที่ทำในตัวอย่าง 3 คือหัวใจของ RAG: สัปดาห์หน้าเราจะเอา "เอกสารที่ค้นมาได้" แทรกเข้า list เดียวกันนี้ ให้มันตอบจากเอกสารของเรา

## Week 2 — RAG: ให้ AI ตอบจากเอกสารของเรา

### RAG คืออะไร (อ่าน 2 นาที)

LLM รู้แค่สิ่งที่มันเคยเรียนมา มันไม่รู้จักระเบียบบริษัทคุณ ถามไปมันก็เดา
**RAG (Retrieval-Augmented Generation)** แก้ด้วยการ "ค้นเอกสารที่เกี่ยวข้อง แล้วแปะให้มันอ่านก่อนตอบ" — เหมือนสอบแบบเปิดหนังสือ

```
เตรียมครั้งเดียว:  เอกสาร (data/*.md) → หั่นเป็นชิ้นตามหัวข้อ → แปลงแต่ละชิ้นเป็นตัวเลข (embedding) → เก็บไว้ (index.json)

ทุกครั้งที่ถาม:   คำถาม → แปลงเป็นตัวเลข → หาชิ้นที่ตัวเลขใกล้ที่สุด 3 ชิ้น (Retrieval)
                → แปะชิ้นนั้นลงใน prompt (Augmented) → ส่งให้ LLM ตอบ (Generation)
```

เทียบกับที่คุณคุ้น:
- **Embedding** = แปลงข้อความเป็น `float[1024]` ที่เก็บ "ความหมาย" ข้อความความหมายคล้ายกัน ตัวเลขจะใกล้กัน
- **Index** = ตารางที่มีคอลัมน์ `text` กับ `vector` (ของเราเก็บเป็นไฟล์ JSON; งานจริงใช้ vector database เช่น pgvector, Azure AI Search, Qdrant)
- **Search** = `SELECT TOP 3 ... ORDER BY similarity DESC` แต่เทียบความหมาย ไม่ใช่ `LIKE '%คำ%'`
- **Prompt** = `messages` list เดิมจาก Week 1 แค่ใส่เอกสารเพิ่มเข้าไป

ข้อมูลตัวอย่างในโฟลเดอร์ [data/](data/) คือคู่มือพนักงานของบริษัทสมมติ "นาวาเทค โซลูชั่น" (การลา, WFH, เบิกค่าใช้จ่าย, IT Security, สวัสดิการ)
โค้ดที่ใช้ร่วมกันอยู่ใน [rag_utils.py](rag_utils.py) — อ่านไฟล์นี้ไล่จากบนลงล่างจะเห็นครบทุกขั้น

### ติดตั้งเพิ่ม (ทำครั้งเดียว)

ดึงโค้ดล่าสุด แล้วดึงโมเดลสำหรับทำ embedding (~1.2 GB) ที่รองรับภาษาไทย:
```powershell
git pull
ollama pull bge-m3
```

### รันตัวอย่าง (ทำตามลำดับ)

```powershell
python 04_embeddings.py   # ดูว่าข้อความกลายเป็นตัวเลขยังไง และเทียบความหมายยังไง
python 05_simple_rag.py   # RAG ทีละขั้น: เทียบคำตอบ "ไม่มี RAG" กับ "มี RAG"
python 06_rag_chat.py     # แชทบอทถาม-ตอบเอกสารบริษัท (พิมพ์ exit เพื่อออก)
```

ครั้งแรกที่รัน 05 หรือ 06 จะสร้างไฟล์ `index.json` (embed เอกสารทั้งหมด) ครั้งต่อไปใช้ไฟล์เดิม ถ้าแก้เอกสารใน `data/` มันจะสร้างใหม่ให้เอง

### ให้สังเกตอะไร

- **ตัวอย่าง 4:** "ลาป่วยต้องมีใบรับรองแพทย์ไหม" กับ "ไม่สบาย หยุดงาน 3 วัน ต้องใช้เอกสารอะไร" ไม่มีคำซ้ำกันเลย แต่คะแนนความใกล้สูงสุด
- **ตัวอย่าง 5:** ไม่มี RAG โมเดลตอบกว้างๆ หรือมั่ว / มี RAG ตอบ "12 วัน ยกไปได้ 5 วัน" ตรงตามเอกสาร และพิมพ์ให้ดูว่าค้นเจอชิ้นไหน คะแนนเท่าไร
- **ตัวอย่าง 6:** ลองถามเรื่องที่ไม่มีในเอกสาร เช่น "บริษัทมีที่จอดรถฟรีไหม" มันต้องตอบว่าไม่พบข้อมูล (เพราะ system prompt สั่งห้ามเดา)

### ลองทำเอง (การบ้าน)

1. เพิ่มไฟล์ `.md` ของคุณเองใน `data/` (บรรทัดแรก `# ชื่อเอกสาร` แล้วแบ่งหัวข้อด้วย `## `) แล้วรัน `06_rag_chat.py` ถามเรื่องในไฟล์นั้น
2. เปลี่ยน `top_k=3` ใน `06_rag_chat.py` เป็น 1 หรือ 5 ดูว่าคำตอบดีขึ้นหรือแย่ลง
3. ลบประโยค "ห้ามเดาเอง" ออกจาก `RAG_SYSTEM_PROMPT` ใน `rag_utils.py` แล้วถามเรื่องที่ไม่มีในเอกสาร ดูว่ามันเริ่มมั่วไหม

### ข้อจำกัดที่ควรรู้

- `qwen2.5:3b` เป็นโมเดลเล็ก บางครั้งอ่านเอกสารผิด (เช่น ถาม "ลาป่วย 3 วันต้องมีใบรับรองแพทย์ไหม" แล้วตอบว่าไม่ต้อง) ถ้าเครื่องมี RAM 16 GB ขึ้นไป ลอง `ollama pull qwen2.5:7b` แล้วแก้ `CHAT_MODEL` ใน `rag_utils.py` จะแม่นขึ้นแต่ช้าลง
- คำถามต่อเนื่องแบบ "แล้วถ้าเป็นพนักงานทดลองงานล่ะ" ค้นเอกสารได้ไม่ดี เพราะเราเอาคำถามสั้นๆ นั้นไปค้นตรงๆ (งานจริงจะให้ LLM เขียนคำถามใหม่ให้ครบก่อนค้น เรียกว่า query rewriting)

## Troubleshooting

| ปัญหา | วิธีแก้ |
|---|---|
| `python` หาไม่เจอ (Windows) | ลอง `py` แทน หรือติดตั้ง Python ใหม่แล้วติ๊ก "Add to PATH" |
| `ollama` หาไม่เจอ | ติดตั้ง Ollama แล้วเปิด terminal ใหม่ (Windows รันเองอยู่แล้ว) |
| สคริปต์บอก connection refused | Ollama ไม่ได้รัน — พิมพ์ `ollama serve` ค้างไว้ใน terminal อีกอัน |
| โมเดลตอบช้า | เครื่องไม่มี GPU จะช้าหน่อย ปกติ รอได้; ถ้าช้ามากเปลี่ยนเป็น `qwen2.5:1.5b` (เล็กลง) โดยแก้ `MODEL_NAME` ในสคริปต์ |
| `pip install` error สีแดง | ลอง `python -m pip install -r requirements.txt` |
| `model "bge-m3" not found` | ยังไม่ได้ดึงโมเดล embedding — รัน `ollama pull bge-m3` |
| คำตอบ RAG ไม่ตรงเอกสาร | ดูชิ้นเอกสารที่ค้นเจอใน `05_simple_rag.py` ก่อน ถ้าค้นถูกแต่ตอบผิด = โมเดลเล็กไป ดูหัวข้อ "ข้อจำกัดที่ควรรู้" |
| แก้ไฟล์ใน `data/` แล้วคำตอบไม่เปลี่ยน | ลบไฟล์ `index.json` แล้วรันใหม่ |
| `UnicodeEncodeError` ตอน print ภาษาไทย | Python บน Windows ใช้ cp1252 — สคริปต์ใน repo นี้แก้ให้แล้ว; ถ้าเขียนเองใส่ `sys.stdout.reconfigure(encoding="utf-8")` หรือรัน `python -X utf8` |
